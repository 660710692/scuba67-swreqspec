# Feature: ยืนยันการชำระเงินด้วย Dynamic QR Code เรียลไทม์ (Real-time Dynamic QR Payment Verification)
Spec ID: SPEC-PAY-001 | Source: สัมภาษณ์ร้านตือ (ปัญหาเงินค้างในระบบ / ตรวจสอบยอดโอน) | Use case: UC-01
Owner: ทีม POS Core | Status: Draft v1 | Updated: 2569-09-09

## Goal
แคชเชียร์และเจ้าของร้าน (พี่เบิร์ด) สามารถสร้าง Dynamic QR Code ตามยอดเงินออเดอร์บนหน้าจอ POS และได้รับสัญญาณยืนยันเงินเข้าบัญชีธนาคารแบบเรียลไทม์ (ภายใน 2 วินาทีหลังลูกค้าโอนสำเร็จ) เพื่อป้องกันปัญหาเงินค้างในระบบโดยไม่มีการตรวจสอบ และช่วยให้ปิดออเดอร์ได้อย่างถูกต้องรวดเร็ว

## Scope
### In scope
- สร้าง Dynamic QR Code (PromptPay) เฉพาะตามยอดรวมของออเดอร์บนหน้าจอ POS พร้อม Expiry Time
- รับสัญญาณการชำระเงินสำเร็จ (Payment Webhook) จากระบบธนาคารแบบเรียลไทม์
- แสดงสถานะ "ชำระเงินสำเร็จ" บนหน้าจอ POS และส่งเสียงแจ้งเตือน (Audio Notification) ที่เครื่อง POS และสมาร์ทโฟนของเจ้าของร้าน
- บันทึกหมายเลขอ้างอิงการโอน (Transaction Reference / Slip Reference ID) ลงในประวัติออเดอร์
- รองรับการตรวจสอบสถานะย้อนหลังด้วยตนเอง (Pending Re-check) หากระบบสื่อสารขัดข้องชั่วคราว

### Out of scope
- การยกเลิกรายการและคืนเงินผ่านระบบธนาคารอัตโนมัติ (Refund Process - UC-05)
- การรับชำระเงินด้วยบัตรเครดิต/เดบิต หรือบัตรกำนัล (Credit Card / Voucher - UC-06)
- การสรุปยอดและกระทบยอดเงินฝากประจำวันกับบัญชีธนาคารใหญ่ (Daily Bank Settlement - UC-12)
- การยืนยันตัวตนแคชเชียร์ (UC-00) - ถือว่าเข้าสู่ระบบเรียบร้อยแล้วก่อนเริ่มรายการ

## Constraints
- CON-TECH-01 ใช้โปรโตคอล HTTPS (TLS 1.3) และ HMAC SHA-256 Signature สำหรับการสื่อสาร Payment Webhook จากระบบธนาคาร
- CON-BIZ-01 บันทึก Audit Log ทุกธุรกรรมชำระเงิน (หมายเลขออเดอร์, ยอดเงิน, เวลา, Transaction Ref ID) และเก็บรักษาข้อมูลไม่น้อยกว่า 2 ปี
- IF-BANK-01 เชื่อมต่อกับ PromptPay Dynamic QR API และ Webhook Service ของธนาคารโดยตรง โดยไม่ผ่านระบบตัวกลางที่ปิดซ่อนข้อมูลเงินเข้า
- IF-POS-01 ทำงานร่วมกับ Edge Local Server ภายในร้าน เพื่อให้หน้าจอแคชเชียร์สลับไปใช้ระบบสแกนสลิปสำรอง (Offline Fallback) หากสัญญาณอินเทอร์เน็ตหลุด

## Requirements
- FR-PAY-01 เมื่อเลือกชำระเงินด้วย QR Code ระบบต้องสร้าง Dynamic QR Code ที่ระบุยอดเงินตรงตามออเดอร์พร้อม Expiry Time (3 นาที) แสดงบนหน้าจอ POS
- FR-PAY-02 เมื่อได้รับการยืนยัน Webhook จากธนาคาร ระบบต้องตรวจสอบยอดเงินและ Transaction Ref ID ให้ตรงกับออเดอร์ แล้วเปลี่ยนสถานะเป็น "ชำระเงินแล้ว" ทันที                        <- UC-01 main flow ขั้น 4
- FR-PAY-03 เมื่อการชำระเงินสำเร็จ ระบบต้องส่งสัญญาณเสียงแจ้งเตือน "ชำระเงินสำเร็จ [ยอดเงิน]" ออกทางลำโพง POS และส่ง Notification ไปยังแอปเจ้าของร้าน                           <- UC-01 main flow ขั้น 5
- FR-PAY-04 หาก Dynamic QR Code หมดอายุ (เกิน 3 นาที) โดยยังไม่ได้รับสัญญาณโอนเงิน ระบบต้องยกเลิก QR Code ชุดนั้น และมีปุ่มให้กดสร้างใหม่                                   <- UC-01 exception 3a
- FR-PAY-05 หากสัญญาณอินเทอร์เน็ตขัดข้องชั่วขณะแต่เงินโอนสำเร็จ Edge Server ต้องบันทึก Transaction ค้างไว้ และซิงค์ขึ้น Cloud ทันทีเมื่อกลับมาเชื่อมต่อได้                      <- UC-01 exception 4a
- FR-PAY-06 ในกรณีเกิดข้อผิดพลาดหรือเงินไม่เข้าทันที ระบบต้องมีปุ่ม "ตรวจสอบยอดเงินค้าง (Pending Re-check)" ให้แคชเชียร์กดดึงสถานะล่าสุดจาก Bank API โดยไม่ต้องโทรตาม Support     <- UC-01 alternative 4b

## Quality Requirements
- NFR-PERF-01 เวลาตอบสนองการสร้าง Dynamic QR Code ต้อง <= 1 วินาที (p95)
- NFR-PERF-02 ระยะเวลาตั้งแต่ลูกค้าโอนสำเร็จ จนถึงการแสดงผลและส่งเสียงแจ้งเตือนบน POS ต้อง <= 2 วินาที (p95)
- NFR-SEC-01 การรับส่งข้อมูลการชำระเงินทั้งหมดต้องผ่านการเข้ารหัส TLS 1.3 และมีการตรวจสอบความถูกต้องด้วย Webhook Secret Key
- NFR-REL-01 ความน่าเชื่อถือของระบบรับสัญญาณชำระเงินต้องมี Availability >= 99.9%
- NFR-USE-01 แคชเชียร์สามารถปิดการขายด้วย Dynamic QR Code ได้สำเร็จภายใน 3 คลิกบนหน้าจอ POS

## Acceptance Criteria
- [ ] AC-PAY-01 (FR-PAY-01, FR-PAY-02)
      Given ออเดอร์ยอดรวม 350 บาท อยู่ในหน้าชำระเงิน
      When  แคชเชียร์เลือกชำระเงินด้วย "Dynamic QR Code" และลูกค้าสแกนจ่ายสำเร็จ
      Then  ระบบแสดง Dynamic QR Code ยอด 350 บาท, รับสัญญาณโอนสำเร็จใน <= 2 วินาที, เปลี่ยนสถานะเป็น "ชำระเงินแล้ว", และส่งเสียงแจ้งเตือน
- [ ] AC-PAY-02 (FR-PAY-03, NFR-PERF-02)
      Given ยอดเงินโอนเข้าบัญชีสำเร็จจากธนาคาร
      When  Bank Webhook ส่งข้อมูลมาถึงระบบ POS
      Then  หน้าจอ POS อัปเดตสถานะพร้อมส่งเสียงแจ้งเตือนสำเร็จ และเจ้าของร้านได้รับการแจ้งเตือนบนสมาร์ทโฟนพร้อมกันใน <= 2 วินาที
- [ ] AC-PAY-03 (FR-PAY-04)
      Given Dynamic QR Code ถูกสร้างขึ้นมาเกิน 3 นาทีและยังไม่มีการโอนเงิน
      When  เวลาครบกำหนด (Timeout)
      Then  ระบบยกเลิก QR Code เดิม แสดงข้อความ "QR Code หมดอายุ" และมีปุ่มให้กดสร้าง QR Code ใหม่
- [ ] AC-PAY-04 (FR-PAY-06)
      Given เกิดปัญหาสัญญาณเครือข่ายขัดข้องชั่วขณะระหว่างสแกน
      When  แคชเชียร์กดปุ่ม "ตรวจสอบยอดเงินค้าง (Pending Re-check)"
      Then  ระบบยิงคำขอ Query ไปยัง Bank API และอัปเดตสถานะเป็นชำระเงินสำเร็จพร้อมแสดง Transaction Ref ID โดยไม่ต้องรอเจ้าหน้าที่
- [ ] AC-PAY-05 (CON-BIZ-01)
      Given รายการชำระเงินเสร็จสมบูรณ์
      When  เปิดดูประวัติออเดอร์
      Then  มี Audit Log บันทึกหมายเลขออเดอร์, ยอดเงิน, เวลาโอนสำเร็จ, และ Transaction Ref ID จากธนาคารอย่างครบถ้วน
